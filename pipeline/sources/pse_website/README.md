# PSE public website source

`PSEWebsiteConnector` captures a bounded set of official public data pages from `www.pse.com.ph`: Market Reports, the news and announcement archive, the press room archive, and Listing Statistics. It does not crawl site navigation, arbitrary links, sitemaps, third-party pages, or linked files. The source catalog is in `catalog.py`.

The pages are rendered with Scrapling's browser fetcher because their report/archive content is populated by JavaScript. Market Reports, announcements, press releases, and listing statistics are extracted from rendered tables, including paginated rows. Each row retains the source columns and links, plus normalized title, date, category, report, and numeric listing-statistic fields where available. A target page that returns no rows is recorded as a required source failure rather than producing empty warehouse records. RSS/Atom is a separate, 15-minute mapped Airflow DAG under the `pse_website` source; feed URLs are validated against official PSE page hosts.

Every page response and run manifest is retained under the `raw` object-store bucket. The lake uses raw, stage, and curated layers: stage files keep deduplicated run deltas, and curated files keep a globally deduplicated `current.parquet` snapshot per dataset. PostgreSQL loads only the stage delta and upserts on `(dataset, record_key)`, preserving the full JSONB source payload alongside typed query fields. dbt builds materialized website record and listing-statistic facts. Generic source rows and page snapshots remain available in the lake; only typed market reports, announcements, press releases, listing statistics, and RSS items enter the warehouse and Next.js viewer.

The daily DAG is `pse_website_public_ingestion`. It runs on the `scrape-browser` Celery queue, so the browser worker must be available. The separate `pse_website_rss_ingestion` DAG maps each configured feed to its own capture, transform, and load task every 15 minutes. Both publish the `pse_website` warehouse asset after the loads succeed.

The focused page crawl defaults to a maximum of 10 pages (four configured targets), two browser workers, and a 0.75-second request interval, further bounded by the Airflow `pse_website_source` pool and the site's `robots.txt`. `PSE_WEBSITE_RSS_FEEDS` accepts comma-separated feeds; its default is `https://www.pse.com.ph/feed/`. `PSE_WEBSITE_MAX_PAGES` bounds the target page count. Browser capture failures and robots-policy failures are recorded in the source manifest and Airflow task logs.

For a manual capture, run `python -m tools.pse_website_fetch --max-pages 4 --workers 2` with object-store configuration available.
